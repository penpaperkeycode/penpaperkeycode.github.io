This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

This is Jeonghoon Kim's academic homepage (https://penpaperkeycode.github.io). It started from the [AcademicPages](https://github.com/academicpages/academicpages.github.io) Jekyll template (a detached fork of Minimal Mistakes), and the homepage now uses its own layout and data files. There are no tests or linter. The only CI is `.github/workflows/pdf.yml`, which reprints the homepage PDF and commits it back to `master` (see **PDF** below). GitHub Pages builds `master` on every push using the `github-pages` gem (Jekyll 3.10 in safe mode, Ruby Sass 3.7.4, kramdown GFM), so **pushing to `master` publishes the live site**. There is no staging environment. The owner often edits files in GitHub's web editor, and the PDF workflow pushes its own commits, so run `git pull --rebase` before working locally.

## Commands

```bash
bundle install                            # first time; if it fails, delete Gemfile.lock (gitignored) and retry
bundle exec jekyll serve -l -H localhost  # http://localhost:4000 with livereload
bundle exec jekyll build                  # one-off build into _site/ (gitignored)
docker compose up                         # serve on :4000 from a ruby:3.2 container (the Dev Container uses this too)
npm install && npm run build:js           # regenerate assets/js/main.min.js after editing its JS sources
node .github/scripts/build-pdf.mjs --site _site --out /tmp/home.pdf  # print any built _site to PDF (needs Chrome)
```

- Production-identical preview without a local Ruby (same Jekyll/Sass versions as GitHub Pages): build in the repo's Docker image with `JEKYLL_ENV=production` and an extra config that overrides the absolute site URL, then serve `_site`:
  `docker build -t jekyll-site . && printf 'url: "http://localhost:4100"\n' > /tmp/preview.yml && docker run --rm -e JEKYLL_ENV=production -v "$PWD":/usr/src/app -v /tmp/preview.yml:/tmp/preview.yml:ro jekyll-site jekyll build --config _config.yml,/tmp/preview.yml && python3 -m http.server 4100 -d _site`
  Links and assets are absolute (`site.url`), so the port you serve on must match the overridden URL.
- On macOS, the README installs Ruby with Homebrew (`brew install ruby`, then `gem install bundler`) instead of using the system Ruby. If you hit gem permission errors, run `bundle config set --local path 'vendor/bundle'`.
- `jekyll serve` does not reload `_config.yml`. Restart the server after you edit it.
- A clean `jekyll build` is the closest thing to a test. Read its output rather than trusting the exit code: Liquid errors abort the build, but malformed YAML front matter only logs a warning and the page renders wrong. A YAML syntax error in `_data/*.yml` fails the GitHub Pages build (red run in the repo's Actions tab) and the live site keeps the previous version.
- The README says to run `chmod -R 777 .` before `docker compose up`. That's only needed if the container user (UID 1000) can't write to the checkout. Because `core.fileMode` is on, the chmod makes git report every tracked file as modified.

## Where the content lives

The homepage (`/`, `_pages/about.md`, `layout: home`) is the only real page. Content is split into data files, each with a "HOW TO ADD" header and a copyable TEMPLATE (remove the leading `# ` from each template line and it is valid YAML):

- `_pages/about.md`: the About paragraph only, plus one `{% include home/... %}` line per section. Its `redirect_from` also makes `/about/`, `/cv/` and `/resume` redirect to `/`.
- `_data/experience.yml` → Work Experience timeline. Per job: `org`, `period` (contains "Present" → current dot), optional `about` (one-line company description), `role`, optional `items_label` + `items` (currently "Focus areas"), optional `earlier` (shown under "Earlier work"), optional `promotions` (`year`/`title`/`team`, newest first; the highest year gets the highlighted dot). An item is a string or `{text, papers, sub}`; `papers` lists ids from `publications.yml` and renders as linked `[N]` numbers (an unknown id renders a visible `??`).
- `_data/publications.yml` → Publications. `highlight:` names are bolded automatically; `lead:` then `coauthor:`, numbered continuously 1..N in file order (the `[N]` references in Work Experience follow automatically). Fields: `id`, `title` (no trailing period), `url`, `authors` (`*` = equal contribution), `venue` (a venue containing "Technical report" gets the green badge, other "Arxiv" venues grey, the rest blue), optional `note`, optional `corresponding: true` (adds † after his name; by his choice only on co-author papers, never on first/co-first ones), optional `links` (`label`: Paper / arXiv / Code / Model). Every link was HTTP-checked when added; don't invent links.
- `_data/education.yml` → Education timeline. `_data/service.yml` → Service section (groups with a label and items: Reviewing, Tech blog).
- `_config.yml` → `title` (masthead, `<title>`), `description`/`og_description`/`og_image` (search and link previews), and `author:` (photo `images/profile-portrait.jpg`, 4:5; `images/profile-square.jpg` is only the link-preview `og_image`; name, bio, employer, location, email, Google Scholar, LinkedIn) rendered by `_includes/home/profile.html`. Only the fields listed in the comment above `author:` appear on the homepage.
- `_data/navigation.yml` → masthead links to the section anchors (`/#work-experience`, `/#education`, `/#publications`, `/#service`).

Facts on the page come from the owner (his CV plus later corrections); verify against official sources (ACL Anthology, OpenReview, PMLR, NeurIPS proceedings, arXiv) before changing titles, author lists or venues, and never publish the phone number from his CV. Keep every value double-quoted in the YAML files; an unquoted `2026: text` bullet still renders, but other slips break the build.

The template's sample content and machinery that the homepage doesn't use were removed in Oct 2026: sample posts and collections, sample pages and PDFs, the old Markdown CV (`_pages/cv.md`), unused layouts and includes (single/archive/talk, sidebar, comments, archives, pagination, TOC), the talk map, the Markdown/CV-JSON generators, the template's issue templates and workflow, the RSS feed (`jekyll-feed`) and MathJax. They are in git history (before commit "Remove unused template content") if ever needed.

## How the site is assembled

- **Layouts:** only `compress` → `default` (head, masthead `<header>`, footer, scripts) → `home` (`<main>`: `_includes/home/profile.html` sticky profile + the page content) exist. The homepage and the 404 page use `home`, and `defaults:` in `_config.yml` makes it the default for any new page.
- **Includes:** `_includes/home/` renders each section from its data file. `inline.html` renders short Markdown strings (opens external links in a new tab with a screen-reader hint, repairs unquoted `key: value` YAML slips); `points.html` renders one labelled bullet list of a job.
- **Liquid gotcha:** a block whose body is only whitespace renders nothing (`{% unless forloop.last %} {% endunless %}` outputs no space). Emit whitespace with an output tag (`{{ " " }}`) instead.
- **HTML compression:** `compress.html` minifies HTML everywhere except `development`, collapsing each page onto one line, so a `//` comment in an inline `<script>` breaks only in production. The inline script in `_includes/head.html` (no-JS class, pre-paint dark theme, `screen.orientation` shim for old Safari, which `main.min.js` would otherwise crash on) is written without `//` comments.
- **JavaScript:** `assets/js/main.min.js` is a committed bundle of `assets/js/_main.js`, `assets/js/plugins/` and vendor libraries (sources are in `exclude:`; rebuild with npm). Site-specific behavior lives in the standalone `assets/js/site-extras.js`, loaded after it with no build step: menu `aria-expanded` and closing behavior, a second greedy-nav layout pass, theme toggle `aria-pressed` and `theme-color`, reduced-motion scrolling, the masthead section highlight, and un-pinning the sticky profile when it doesn't fit.
- **CSS:** `assets/css/main.scss` imports the `_sass/` partials (empty front matter required); homepage styles, including the `#main` page container, are in `_sass/layout/_home.scss`. Ruby Sass 3.7.4: no `@use`/`math.div`, and CSS `min()`/`max()`/`clamp()` get evaluated by Sass. Colors are CSS variables defined in both `_sass/theme/_default.scss` (`:root`) and `_sass/theme/_dark.scss` (`html[data-theme="dark"]`, inside `@media screen` so printouts use the light colors); add any new color to both. The palette (his choice, Oct 2026) is neutral grays, text-safe blue links, purple group labels, light blue/green/gray badges and one green→blue→purple signature gradient, used only for the masthead's top bar (`--signature-stops`) and for the current dots and the active-section bar (`--signature-stops-ui`; every stop ≥ 3:1 against the page and the dot's halo). Bright palette colors fail as text on white, so text uses darker shades of the same hues (WCAG AA in both themes). The dark background #121212 is also hardcoded as `theme-color` in `_includes/head/custom.html` and `assets/js/site-extras.js`; change all three together. Anchor offsets under the fixed masthead come from `html { scroll-padding-top }` in `_sass/layout/_base.scss`.
- **Custom snippets:** `<head>` additions go in `_includes/head/custom.html` (favicons, theme-color, Academicons; add MathJax back there if a page ever needs math); footer additions in `_includes/footer/custom.html`. For internal URLs, use `{% include base_path %}` and prefix the path with `{{ base_path }}`.
- **PDF:** the profile's PDF link downloads `files/Jeonghoon_Kim.pdf` and appears only once that file exists (`site.static_files` check in `profile.html`). Never edit the PDF by hand. `.github/workflows/pdf.yml` runs on pushes to `master` that touch `_config.yml`, `_data`, `_includes`, `_layouts`, `_pages`, `_sass`, `assets` or `images`, and can also be run by hand from the Actions tab. It builds `_site` with `actions/jekyll-build-pages` (the same build as Pages), installs `fonts-inter`, runs `.github/scripts/build-pdf.mjs`, and commits the PDF as github-actions[bot] when it changed. That push starts the normal Pages build. The script drives headless Chrome over `--remote-debugging-pipe` (no npm packages). It answers requests for the build's own URL (its canonical link, or `--url`) from `_site` and blocks all others, so the PDF's links point to the live site. A blocked stylesheet, image or font is an error. It prints A4 with a footer: title, host, "Updated" (the date of the last commit touching `_config.yml`/`_data`/`_pages`) and page numbers. It fails if an [N] link's target is missing from the PDF, and it keeps the existing file when only Chrome's timestamps differ. The page fades in on load (`intro` animation), so the script emulates reduced motion and waits for animations; otherwise the PDF comes out semi-transparent. The layout is the print stylesheet (`@media print` in `_home.scss`), which a visitor also gets when printing. In it, headings stay with what follows, and papers, bullets and short entries don't split, while an entry with labelled lists may. Nothing may stick out of the page box: Chrome would shrink every page and drop link targets, so the `.pub-list`/`.pub` hover bleed is removed. The email address is printed as text (`data-print`), and `.pub__links` and `.profile__pdf` are hidden. `$sans-serif` lists Inter before Roboto so the Linux runner sets the PDF in Inter; a print made on macOS uses San Francisco instead.
- **Plugins:** the site uses only `jekyll-sitemap` and `jekyll-redirect-from` (listed in `plugins:`/`whitelist:` and the Gemfile). Only plugins that GitHub Pages supports run in production; a new gem or a `_plugins/` directory can work in a local `serve` and then silently do nothing once deployed.
